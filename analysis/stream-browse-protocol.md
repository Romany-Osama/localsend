# تصميم ميزة Stream & Browse

## المبدأ

الميزة الجديدة ستعمل كطبقة مستقلة فوق خادم HTTP المحلي الموجود في LocalSend. لن نغير مسارات الإرسال والاستقبال الأصلية، ولن نستخدم وجود الجهاز على نفس الشبكة كإذن تلقائي. الجهاز المستضيف يحدد نطاق المشاركة، والجهاز الطالب يتصفح أسماء وبيانات وصفية فقط، ثم يطلب الوصول إلى ملف محدد. لا يبدأ إرسال محتوى الملف إلا بعد موافقة الجهاز المستضيف.

## دورة الاستخدام

1. يكتشف الجهازان بعضهما عبر LocalSend بالطريقة الحالية.
2. يختار المستخدم على الجهاز الطالب جهازًا بعيدًا ثم يفتح **Browse & Stream**.
3. يرسل الجهاز الطالب طلب فتح جلسة تصفح. يوافق الجهاز المستضيف على الجهاز أو يرفضه.
4. بعد القبول، يعرض المستضيف جذور المشاركة المسموح بها؛ يمكن أن تكون مجلدات محددة، أو كل قرص بعد تفعيل صريح من المستخدم.
5. يتصفح الجهاز الطالب المجلدات. هذه العملية تعرض metadata فقط ولا تقرأ محتوى الملفات.
6. عند اختيار ملف، يرسل الجهاز الطالب طلب وصول مستقل. يظهر على الجهاز المستضيف اسم الجهاز الطالب، المسار، الحجم، ونوع العملية: تشغيل/فتح أو تنزيل.
7. بعد الموافقة، يعيد الخادم تصريحًا مؤقتًا للملف، ويبدأ الجهاز الطالب طلب stream مع دعم `Range`.
8. يمكن للمستضيف إلغاء التصريح أو إيقاف الجلسة في أي وقت. يظل التصريح قراءة فقط ولا يسمح بالكتابة أو الحذف أو التنفيذ.

## المسارات المقترحة

| المسار | الغرض | المحتوى |
|---|---|---|
| `POST /api/localsend/stream/v1/session` | طلب جلسة تصفح | هوية الجهاز، النسخة، ونوع العميل |
| `GET /api/localsend/stream/v1/roots?sessionId=...` | عرض جذور المشاركة | معرف الجذر، الاسم الظاهر، ونوعه |
| `GET /api/localsend/stream/v1/entries?sessionId=...&rootId=...&path=...` | عرض محتويات مجلد | أسماء وعلامات الملفات والمجلدات وmetadata فقط |
| `POST /api/localsend/stream/v1/file-request` | طلب قراءة ملف محدد | session، root، path، العملية المطلوبة |
| `POST /api/localsend/stream/v1/file-request/{id}/cancel` | إلغاء طلب أو تصريح | معرف الطلب |
| `GET /api/localsend/stream/v1/stream/{id}` | بث المحتوى | تصريح مؤقت، مع `Range` و`If-Range` اختياريًا |
| `POST /api/localsend/stream/v1/session/{id}/revoke` | إغلاق جلسة التصفح | معرف الجلسة |

## نماذج البيانات

### جلسة التصفح

```json
{
  "sessionId": "uuid",
  "deviceId": "stable-peer-id",
  "mode": "read-only",
  "expiresAt": "timestamp",
  "roots": ["root-id"]
}
```

### عنصر مجلد

```json
{
  "entryId": "opaque-id",
  "name": "movie.mp4",
  "kind": "file",
  "size": 734003200,
  "modifiedAt": "timestamp",
  "mimeType": "video/mp4",
  "streamable": true
}
```

لن نرسل المسار الحقيقي الخام كمعرف دائم. سيستخدم الخادم معرفات opaque مرتبطة بالجلسة، أو مسارًا نسبيًا يتحقق منه الخادم، لمنع تخزين أو إعادة استخدام مسارات خارج نطاق المشاركة.

### طلب ملف

```json
{
  "sessionId": "uuid",
  "entryId": "opaque-id",
  "purpose": "play"
}
```

الرد المقبول يحتوي على `requestId` أو `streamId` قصير العمر. لا يُقبل أي stream لا يرتبط بجلسة صحيحة وبهوية الجهاز وبالملف الذي تمت الموافقة عليه.

## بث الفيديو والملفات

سيستخدم endpoint البث استجابة `200 OK` للملف كاملًا أو `206 Partial Content` عند وجود `Range`. يجب إرسال `Content-Length` و`Content-Range` و`Accept-Ranges: bytes` و`Content-Type` الصحيح. هذا يسمح لمشغلات الفيديو بالتقديم والتأخير وقراءة أجزاء الملف عند الحاجة بدل تحميله كله.

لملفات Android التي تأتي من Storage Access Framework، يجب استخدام descriptor أو seekable source إن كان متاحًا، مع fallback آمن إلى streaming متسلسل عندما لا يدعم المصدر seek. على أنظمة الكمبيوتر، يجب فتح الملف للقراءة فقط والتحقق من أن المسار النهائي يقع داخل الجذر المصرح به بعد حل symlinks، لمنع path traversal.

## الأمان

الموافقة على جلسة التصفح تسمح برؤية metadata ضمن الجذور المحددة، لكنها لا تلغي الموافقة لكل ملف. لكل طلب ملف شاشة موافقة مستقلة افتراضيًا. الجلسة والتصاريح مؤقتة، مرتبطة بهوية الجهاز وبالشهادة/المفتاح المعروف من LocalSend حيثما كان ذلك متاحًا، وبعنوان الاتصال كطبقة إضافية فقط. لا توجد عمليات كتابة أو حذف أو تنفيذ في الإصدار الأول.

خيار **كل الهارد** سيحوّل الأقراص إلى جذور مشاركة يحددها الجهاز المستضيف. يجب أن يؤكد المستخدم تحذيرًا واضحًا، ويظل الوصول قراءة فقط. يجب إخفاء الملفات الحساسة أو ملفات النظام افتراضيًا على الأقل في الواجهة، مع عدم الاعتماد على الإخفاء وحده كحماية.

## توافق المنصات

سيكون البروتوكول في `packages/core`، بينما تنفذ Flutter طبقة اختيار الملفات وواجهات الموافقة والمشغل. نسخة الكمبيوتر تستطيع اختيار مجلدات أو أقراص مباشرة. نسخة Android تستخدم مسارات عادية أو Android SAF. نسخة iOS ستحتاج مجلدات يختارها المستخدم ضمن حدود sandbox وقيود النظام؛ لن نعد بوصول كامل إلى القرص على iOS.

## قرارات الإصدار الأول

الإصدار الأول يركز على: تصفح metadata، طلب موافقة لكل ملف، بث الفيديو والملفات للقراءة فقط، دعم Range على الكمبيوتر وAndroid حيث يسمح المصدر، وإلغاء الجلسة. التحويل اللحظي للفيديو، الوصول عبر الإنترنت، DLNA/Chromecast، وعمليات الكتابة تؤجل إلى مراحل مستقلة.
