# خلاصة فحص LocalSend

## النتيجة

المستودع الحالي هو تطبيق Flutter متعدد المنصات مع طبقة Rust مشتركة لخادم HTTP وبروتوكول LocalSend. الإصدار الذي تم جلبه هو `v1.18.2`، والفرع الأصلي هو `localsend/localsend`.

| الجزء | الدور | صلته بالميزة الجديدة |
|---|---|---|
| `packages/core` | بروتوكول الاكتشاف والـ HTTP والنماذج المشتركة | المكان الطبيعي لإضافة DTOs ومسارات browse/request/stream |
| `packages/core/src/http/server` | خادم HTTP المشترك على الأجهزة | يحتوي على المصادقة الحالية، الجلسات، والتحقق من هوية العميل |
| `packages/core/src/http/server/web.rs` | تدفق مشاركة ملفات الويب الحالي | أقرب أساس؛ يحتوي على جلسة موافقة ثم بث محتوى الملف، لكنه لا يدعم Range حاليًا |
| `app/lib/provider/network/server/controller` | ربط أحداث Rust بواجهة Flutter ومخازن الملفات | يعالج الموافقة الحالية ويحل مسار الملف أو Android SAF |
| `app/lib/provider/network/server/server_provider.dart` | تشغيل وإيقاف الخادم وتوزيع الأحداث | يحتاج ربط أحداث الميزة الجديدة دون تغيير تدفق LocalSend الأصلي |
| `packages/core/src/model/transfer.rs` | تمثيل محتوى الملفات وتدفقه على شكل chunks | يمكن توسيعه بمصدر قراءة جزئي أو تمرير offset/length |

## التدفق الموجود القابل لإعادة الاستخدام

مسار web send الحالي ينشئ طلب `prepare-download`، ثم يرسل حدث `PrepareDownload` إلى التطبيق وينتظر قرار المستخدم. عند القبول ينشئ جلسة مرتبطة بعنوان العميل، ثم يرسل قائمة الملفات. عند طلب ملف، يرسل حدث `FileDownload` إلى التطبيق، الذي يعيد `FileContent`، وبعد ذلك يبث الخادم البيانات إلى العميل.

هذا يطابق جزءًا كبيرًا من المطلوب: جهاز يطلب ملفًا، والجهاز الذي يحتوي عليه يوافق، ثم يقرأ العميل المحتوى عبر الشبكة بدل نسخ الملف كاملًا. لكن المسار الحالي يعرض قائمة ملفات ثابتة مهيأة مسبقًا، ولا يقدم تصفحًا لمجلدات أو أقراص، ولا يعالج HTTP `Range` و`Content-Range` اللازمين لتقديم الفيديو والتقديم والتأخير بكفاءة.

## ملاحظات أمنية

الموافقة يجب أن تكون مطلوبة لكل ملف حتى لو كان الجهاز معروفًا أو سبق منحه صلاحية التصفح. جلسة التصفح لا تكفي وحدها لبدء قراءة المحتوى. الوصول الافتراضي ينبغي أن يكون قراءة فقط، مع ربط الجلسة بهوية العميل وبعنوانه، وإمكانية إبطال الجلسة. خيار كل الأقراص يمكن توفيره، لكنه يجب أن يكون اختيارًا صريحًا من الجهاز المصدر وليس نتيجة كون الجهازين على نفس الشبكة.

## قرار هندسي مبدئي

سنضيف بروتوكولًا مستقلًا ومُسمى بوضوح داخل خادم HTTP الحالي بدل تعديل سلوك الإرسال والاستقبال الأصلي. يتكون مبدئيًا من: فتح جلسة تصفح، طلب قائمة مجلدات/ملفات، إرسال طلب موافقة لملف محدد، ثم بدء stream يدعم `Range`. ستبقى مسارات LocalSend الأصلية كما هي، وستضاف الواجهات والأحداث الجديدة كطبقة اختيارية.
